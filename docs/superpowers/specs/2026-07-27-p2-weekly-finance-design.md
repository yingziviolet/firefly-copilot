# P2 周报、订阅管家与自然语言查账设计

## 目标

在不增加依赖、不接入邮箱和信用卡账单的前提下，为 Firefly Copilot 增加三个适合真实使用和面试展示的功能：

1. 每周一次企业微信财务汇总。
2. 订阅周期与涨价检测。
3. `/review` 内受限的自然语言查账。

项目继续保持单用户、自托管定位；公开仓库不包含个人账目、密钥或特定商户配置。

## 周报推送

新增一个 Celery beat 周任务，默认每周一 09:00 执行，统计刚结束的完整自然周（周一 00:00 至周日 23:59）。

任务只调用一次 `notify()`，消息按以下顺序组成：

- 时间范围；
- 总收入、总支出、净额与交易笔数；
- 支出分类排行；
- 订阅清单与涨价提醒；
- 疑似重复扣费。

无异常时仍发送一条完整周报，并明确写“本周未发现订阅涨价或重复扣费”。查询 Firefly 失败时不发送残缺报告，只记录一次结构化错误日志。

原每日重复扣费任务退出 beat 调度，重复检测并入周报。其纯计算逻辑保留复用，避免同一周连续推送多条告警。

## 订阅管家

第一版仅依据 Firefly 中的历史支出识别，不建立新数据表：

- 对商户名进行现有方式的归一化；
- 同一商户至少出现三次扣费；
- 相邻扣费间隔落在月度周期窗口内时视为疑似订阅；
- 比较最近两次金额，最新金额更高则标记涨价；
- 报告持续扣费订阅，但不声称能够判断用户是否实际使用。

金额统一使用 `Decimal`，日期统一从 Firefly 返回值解析。识别结果是普通数据结构，供周报格式化和单元测试复用。

## 自然语言查账

在 `/review` 增加查账输入框和结果提示。查询链路为：

1. LLM 把用户问题转换为 Pydantic 校验的受限参数；
2. 参数只允许时间范围、收入/支出、分类、商户，以及“金额合计/笔数”两种聚合；
3. 应用调用 Firefly REST API 获取交易并在本地聚合；
4. 页面显示确定性结果。

LLM 不生成 SQL、URL 或可执行表达式。时间范围必须有明确起止日期；模型输出无效、Firefly 不可达或问题超出支持范围时，页面返回可理解的错误提示，不执行模糊查询。

## 配置与公开使用

沿用现有 `ANTHROPIC_*`、`FIREFLY_*`、`WECOM_WEBHOOK_URL` 和 `CONSOLE_TOKEN`。周报默认周一 09:00，首版不新增复杂调度配置；其他时区继续使用现有 Celery 时区设置。

README 增加功能说明、支持的查账示例和周报行为。`.env.example` 只写占位说明，不写真实凭据。

## 错误处理

- Firefly 查询失败：周报不推送；查账页面显示失败提示。
- LLM 解析失败：查账页面提示当前支持的问法。
- 企业微信发送失败：记录一次日志，不自动重复推送，避免刷屏。
- 单条交易字段异常：跳过该条并继续统计，其余有效交易仍进入报告。

## 测试

采用现有 pytest、假 Firefly 客户端和通知替身：

- 周报内容覆盖收入、支出、分类排行，且整轮只通知一次；
- 无异常时仍生成完整消息；
- Firefly 失败时不通知；
- 月度周期识别、涨价识别与非订阅排除；
- 查账参数越界被拒绝；
- 查账按时间、方向、分类或商户过滤后正确聚合；
- `/review` 提交查询后展示结果或明确错误。

不引入浏览器测试框架、缓存、额外数据库表或多用户权限系统。
