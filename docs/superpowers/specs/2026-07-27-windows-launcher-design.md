# Windows 一键启动器设计

## 目标

为已经完成 `.env` 配置的 Windows 用户提供一个无需输入命令的入口：

1. 双击项目根目录的 `启动记账系统.cmd`。
2. 点击“启动并打开复核台”。
3. 启动器自动拉起 Docker Desktop、启动项目容器、等待 API 就绪，并打开 `http://127.0.0.1:8000/review`。

现有 Docker Compose、命令行用法和 Web 页面保持不变，Linux 用户仍按 README 操作。

## 最小方案

只增加两个文件：

- `启动记账系统.cmd`：双击入口，调用 PowerShell。
- `scripts/launcher.ps1`：使用 Windows 自带的 WinForms 显示控制面板并执行操作。

不引入 Electron、Tauri、Node.js 或新的 Python 依赖，也不把密钥复制到启动器中。

## 控制面板

窗口显示当前状态和以下按钮：

- **启动并打开复核台**：主按钮，完成 Docker Desktop → Compose 服务 → 健康检查 → 打开复核台的完整流程。
- **打开复核台**：服务已运行时直接打开 `/review`。
- **打开 Firefly III**：打开 `http://127.0.0.1:8080` 查看原始账目和报表。
- **立即补发本周周报**：在 worker 容器中执行现有 `send_weekly_digest` 任务，并在窗口中显示成功或失败。
- **查看运行状态**：显示 `docker compose ps` 的简要结果。
- **停止服务**：执行 `docker compose stop`，保留数据库、账目和容器，下次可继续启动。

主启动流程在隐藏的 PowerShell 子进程中执行，窗口保持可响应。启动器轮询 API 健康状态；成功后自动打开浏览器。

## 配置与安全

- 启动器只读取项目现有的 `.env`，不展示或记录 PAT、API Key、Webhook 等值。
- `.env` 不存在时停止启动，并提示先从 `.env.example` 配置。
- 复核台使用现有 `CONSOLE_TOKEN`；若已配置，启动器通过一次性查询参数打开页面，由现有应用完成认证处理。
- Docker Desktop 未安装时给出明确提示，不尝试下载安装软件。

## 定时推送说明

周报仍由本机 Celery Beat 在每周一 09:00（`Asia/Shanghai`）触发。本机电脑关机、休眠或 Docker Desktop 未运行时，任务不会执行，也不会在开机后自动补跑。

控制面板通过两种方式降低遗漏影响：

- 启动成功后明确显示“定时推送依赖本机和 Docker 保持运行”。
- 提供“立即补发本周周报”按钮，由用户手动补发。

本轮不增加 Windows 开机自启或云端常驻部署；需要无人值守推送时再单独部署到云服务器。

## 启动与错误处理

1. 检查 `.env` 和 Docker CLI。
2. Docker 引擎不可用时，尝试启动默认安装位置的 Docker Desktop。
3. 等待 Docker 引擎可用，超时后显示原因并允许重试。
4. 已有项目镜像时执行 `docker compose up -d`；首次运行或镜像缺失时复用现有 `scripts/setup.ps1`。
5. 等待 `/healthz` 返回成功；失败时提示用户点击“查看运行状态”。
6. 健康后打开复核台。

所有命令都在项目目录执行。停止操作只使用 `docker compose stop`，不删除容器、卷或账目数据。

## 验证

- 为 `launcher.ps1` 提供 `-SelfTest`，用临时配置验证 `.env` 解析、复核台 URL 生成和缺失配置分支，不启动 GUI 或 Docker。
- 在本机执行 `-SelfTest`。
- 实际点击主按钮，确认 Docker 服务启动、`/healthz` 正常并自动打开复核台。
- 点击周报按钮，确认企业微信收到一条完整周报。
- 点击停止按钮后确认数据卷未被删除，再次启动仍可看到原有账目。

## 不在本轮范围

- 密钥填写向导。
- 开机自启和后台托盘常驻。
- 打包为 `.exe` 安装包。
- 云端部署、GUI 图表或桌面客户端。

这些能力只有在一键控制面板验证好用后再考虑。
