# 自然语言查账归一化设计

## 目标

提高自然语言查账的稳定性，让用户按自然习惯提问。DeepSeek 负责宽松理解问题，程序负责转换、校验、查询和精确计算。

用户回答必须明确显示：

- 查询月份或日期范围。
- 收入还是支出。
- 分类和/或商户。
- 金额合计或交易笔数。

## 处理流程

```text
用户问题
  → DeepSeek 提取宽松的 RawFinanceIntent
  → 本地归一化中英文别名
  → 转换为严格的 FinanceQuery
  → Firefly 查询
  → 程序精确聚合
  → 中文结果
```

DeepSeek 不接收账单明细、不生成 SQL，也不负责金额计算。

## 宽松意图层

新增 `RawFinanceIntent`，所有字段先按普通字符串接收，避免 DeepSeek 返回中文时被 SDK 提前拒绝：

- `start`、`end`：模型根据今天日期输出的起止日期字符串。
- `transaction_type`：允许“支出”“消费”“收入”或英文值。
- `category`：用户所说的消费部分，例如“餐饮”“交通”。
- `merchant`：具体商户，例如“美团”“星巴克”。
- `metric`：允许“金额”“合计”“笔数”“次数”或英文值。

本地转换器把 `RawFinanceIntent` 转成现有 `FinanceQuery`。只有转换后的严格参数才能进入 Firefly 查询。

## 参数归一化

### 收支方向

- `支出`、`消费`、`expense` → `withdrawal`
- `收入`、`入账`、`income` → `deposit`
- 已规范的 `withdrawal`、`deposit` 保持不变

### 统计方式

- `金额`、`合计`、`总额`、`sum` → `sum`
- `笔数`、`次数`、`count` → `count`

### 分类和商户

- DeepSeek 分别输出 `category` 与 `merchant`。
- 提示词带上系统已有分类名称，例如“餐饮”“交通”，要求优先从中选择。
- “美团”“星巴克”等具体对象进入商户字段。
- “餐饮支出”“交通消费”等值在本地去掉“支出/消费”后再匹配已有分类。
- 回答中分别标明“分类”和“商户”，避免用户不知道实际过滤了什么。

## 时间语义

以 2026-07-27 为例：

- “本月” → 2026-07-01 至 2026-07-27。
- “上月” → 2026-06-01 至 2026-06-30。
- “这两个月” → 2026-06-01 至 2026-07-27，即上一个完整自然月加本月至今。
- “最近两个月” → 2026-05-27 至 2026-07-27，即滚动两个月。
- “六月” → 2026-06-01 至 2026-06-30。
- “今年” → 2026-01-01 至 2026-07-27。

DeepSeek 负责初次识别；程序对以上常见表达执行确定性校正，防止同一句话偶尔得到不同日期。

“一个半月”“45 天内”等滚动时间由 DeepSeek 转换为起止日期；程序校验日期顺序和最长 366 天范围。问题未提供时间时，默认查询本月 1 日至今天。

## 重试与错误提示

- `RawFinanceIntent` 无法转换成严格查询参数时，携带错误原因和允许值自动重试 DeepSeek 一次。
- 第二次仍失败时提示“没能识别查询条件，请尝试：六月餐饮支出多少”。
- Firefly 不可用时提示“账目服务暂时不可用，请确认 Docker/Firefly 正在运行”。
- 不再把模型解析错误和账目服务错误合并成同一句提示。

日志记录失败阶段和错误类型，但不记录 Key、Webhook 或完整账单。

## 回答格式

示例：

```text
查询结果：2026年6月至7月，支出，分类「餐饮」，合计 264.53 CNY
```

```text
查询结果：2026年6月，支出，商户包含「美团」，合计 74.57 CNY
```

```text
查询结果：2026年1月至7月，支出，分类「交通」，共 18 笔
```

无匹配结果时仍显示系统识别出的月份、方向和过滤条件，并明确回答 `0.00 CNY` 或 `0 笔`。

对于“1个半月内交通花了多少钱”，回答先展示理解结果：

```text
已理解：2026-06-12 至 2026-07-27，交通支出，金额合计
查询结果：合计 368.20 CNY
```

## 验证

- 模型返回 `type="支出"` 时仍能查询。
- 模型返回 `metric="笔数"` 时转换为 `count`。
- 模型返回中文 `RawFinanceIntent` 后能转换成严格 `FinanceQuery`。
- “这两个月餐饮花了多少”在 2026-07-27 固定为 2026-06-01 至 2026-07-27。
- “六月在美团花了多少”识别为六月、支出、商户美团。
- “1个半月内交通花了多少钱”识别为滚动约 45 天、支出、分类交通、金额合计。
- 未提供时间时使用本月至今。
- DeepSeek 校验失败与 Firefly 离线显示不同提示。
- 所有既有测试继续通过。

## 不在本轮范围

- 让模型读取全部账单并自行计算。
- 任意 SQL 查询。
- 多轮对话和上下文记忆。
- 图表和月度趋势可视化。
- 修改数据库、Firefly、上传、记账、周报或订阅功能。
